Record an actual, distinct session using the supplied exact product. Its TRY or IMP gives the full repository_path and source_commit. Check that the operated source matches that commit. An IMP may formally cover only part of that source; using its provisional CLI does not extend the acceptance claim.

Inspect prior_uses before recording another session. A second use of the same source needs a new publication operation, not a new product revision or another canonical execution. For recovery of an uncertain publication, inspect settlement and retain the original operation. A copied transcript or reused execution receipt is not a new session.

Copy the candidate's exact observes link to product. Supply title, actor_kind, actor, occurred_at, scenario, observed_outcome, evidence_reference, assessment and limitations. Use agent for actual agent operation, user for actual human use, and scripted for an automated fixture. Give the time of use in ISO 8601 format. Record observed, problem or inconclusive according to the session. Preserve the actual input/output transcript in the Markdown body and reference the durable full session log. Describe expected versus observed behavior and what the session did not establish. These are authored accounts; the kernel does not authenticate their actor, time or external evidence. Do not author a receipt or claim kernel-attested execution.

This experimental opt-in profile requires one actual-use account for each current accepted implementation lacking an authentic prior account. Honest observed, problem and inconclusive accounts all satisfy this evidence duty; never manufacture a successful outcome. After the first account, optional repeated operational use remains available. This record neither verifies requirements nor accepts a product. OBS and RES retain their canonical execution contracts. Request stakeholder direction through the appropriate feedback or change action when a decision is needed; each session does not require a stakeholder decision.
